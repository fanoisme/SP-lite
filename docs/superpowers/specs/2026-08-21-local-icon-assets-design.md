# Local Icon Assets Design

**Date:** 2026-08-21
**Status:** Approved for implementation planning

## Problem

SP-lite renders most icons through Material Symbols ligature text. Although the
font is stored locally, the bundled WOFF2 file is about 3.95 MB. Until that font
loads, users on slow connections can see raw names such as
`admin_panel_settings` instead of icons.

The application also contains inline SVG and SVG data URIs. They do not depend
on an external service, but keeping icon artwork in component templates makes
the icon system inconsistent and harder to audit.

## Goal

All application-owned icons and illustrations must come from versioned local
assets. No icon may depend on a web font or expose a text ligature while
loading. Icons must remain sharp, lightweight, and compatible with the current
color and sizing rules.

## Scope

### Included

- Replace every `material-symbols-outlined` use with a shared icon component.
- Replace the existing `LiIcon` font implementation with the same local asset
  system while preserving its public props where practical.
- Add one local SVG file for every icon name used by the application.
- Move reusable inline SVG artwork and SVG data URIs into local assets.
- Move the SP-lite logo mark into a local asset while preserving its current
  presentation and motion where practical.
- Remove the Material Symbols font declaration and its 3.95 MB font file once
  no consumer remains.
- Preserve accessible names on meaningful icons and mark decorative icons as
  hidden from assistive technology.

### Excluded

- QR images generated at runtime.
- User-uploaded images.
- Extracted video frames and other object/data URLs generated by features.
- Content rendered inside user-generated HTML or PDF previews.
- Unrelated visual redesigns.

## Architecture

### Asset directory

Application-owned artwork will live under:

```text
src/assets/icons/
src/assets/brand/
```

Icon filenames use kebab-case semantic names matching the current registry
names, for example `admin-panel-settings.svg`.

### Shared icon component

A shared `LiIcon` implementation resolves a supported icon name to a statically
imported local SVG URL. Monochrome icons are rendered through a CSS mask so
they inherit `currentColor`, hover states, disabled states, and existing design
tokens without requiring separate color variants.

The component provides:

- name-based lookup
- existing size presets plus compatibility with current CSS sizing
- inherited or explicit color
- decorative and labelled accessibility modes
- a deterministic missing-icon fallback that never renders the icon name

Direct Material Symbols spans will be migrated to this component. Dynamic icon
names in module registries, route metadata, dashboard cards, and DD navigation
continue to use stable string identifiers.

### Non-monochrome artwork

Brand artwork and any illustration requiring multiple colors will be rendered
as normal local image assets rather than masks. The logo component remains the
public wrapper for sizing, subtitle, and motion behavior.

## Loading behavior

Vite imports and fingerprints every referenced asset. The generated site never
requests Google Fonts, an icon CDN, or another third-party icon service.

Before an icon asset is available, its fixed-size box remains empty. Raw icon
names are never inserted into the DOM, so slow or failed asset loading cannot
produce visible ligature text or layout shifts.

## Migration

1. Inventory all static and dynamic icon names.
2. Add matching local SVG assets and an explicit icon registry.
3. Rework `LiIcon` to use the registry.
4. Replace direct Material Symbols markup throughout the application.
5. Externalize reusable inline SVG and SVG data URIs.
6. Externalize the logo artwork through `LiLogo`.
7. Remove Material Symbols CSS and font files.
8. Search the repository for remaining icon-font and inline-SVG usage.

## Error handling

- Unknown icon names produce an empty fixed-size element and a development
  warning, never visible text.
- Missing asset imports fail the production build.
- Image errors do not substitute the filename or icon name into the UI.

## Verification

- `npm run build` succeeds.
- Repository search finds no active `material-symbols-outlined` markup,
  Material Symbols font declarations, inline `<svg>` elements, or SVG data
  URIs in application source.
- Every icon-bearing route is checked in the production build.
- Icon color, size, active, hover, disabled, loading, and spinning states remain
  visually correct.
- Browser requests show no external font or icon hosts.
- Slow-network testing never displays raw icon names.
- Existing responsive layouts and accessible labels remain intact.

## Acceptance criteria

- All application-owned icons and illustrations are tracked local assets.
- No icon uses a font ligature.
- No raw icon identifier can appear as visible fallback text.
- The Material Symbols font is absent from the production output.
- Dynamic feature images continue to work unchanged.
- Production build completes successfully.
